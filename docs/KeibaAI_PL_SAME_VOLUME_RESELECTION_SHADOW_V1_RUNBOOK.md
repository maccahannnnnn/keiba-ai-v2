# PL same-volume reselection shadow runbook

This is an additive Python API, not a Production entrypoint. Do not start prospective evidence until the independent Claude review passes and Human gives separate final approval. Previous 10/17–10/18 smoke results do not count toward prospective evidence.

1. `build_pre(current_root, knowledge_root)` checks frozen protocol/model/manifest/PL code hashes and the Current prediction manifest, then runs only the existing PL Forward inference. It does not read Results or change Current. Current PRE provenance must bind the engine, evaluation, and knowledge semantic tree digests as well as the runner, run_new, shadow engine and trace schema. The 10/17 and 10/18 legacy provenance lacks those three PRE-time tree digests; it is not evidence-eligible and no present-day tree is asserted to have been the historical tree.
2. `freeze_pre(selection, new_output_root, first_start_evidence=..., first_start_evidence_sha=..., authorization=..., authorization_sha=...)` requires a new output directory. The authorization JSON must record `protocol_sha256`, the exact `implementation_sha256`, `claude_implementation_review: "PASS"`, and `human_final_implementation_approval: true`. The schedule evidence JSON must contain the compact `date` and timezone-aware `first_start_at`; its separately verified source and SHA must be supplied by the operator. The code checks the reported first start against its clock but does not independently authenticate the schedule's origin. Human review of that authority is required. Record the SHA256 of `selection_freeze.json` externally as the immutable POST authority.
3. `post_from_frozen(pre_root, primary_result, auxiliary_result, new_output_root, expected_freeze_sha256=...)` checks the externally retained freeze SHA and time boundary before the first Result read, validates the two result lists, and writes a new POST. It does not modify PRE or input Results.
4. `summarize_block(posts)` accepts a single environment-fingerprint block. Mixed blocks fail closed. It reports paired and all-inference-success headline denominators separately; inference failures and unequal valid-selection counts are excluded from the paired bootstrap. No historical smoke is allowed into the prospective block.

The caller must independently verify the authorization and schedule provenance, provide evidence of their identity and preserve the freeze SHA before invoking POST. The existence of this runbook or implementation does not grant that authority.

Human operational rule: evidence-eligible PRE must be formally frozen on the preceding day or by 09:00 JST on race day. A freeze after 09:00 JST on race day is not eligible for EXP-024 evidence. This is an operational governance rule, not a code-enforced gate. Only the formal `post.json` produced by `post_from_frozen` is used for formal evidence aggregation.
